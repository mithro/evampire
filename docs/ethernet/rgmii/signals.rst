RGMII and its signals
=====================

What RGMII is, the six signals it uses in each direction, and how it relates
to the older MII and GMII interfaces.

.. _rgmii-what:

Role of RGMII
-------------

An Ethernet port is split between two jobs:

Ethernet transceiver
   The :term:`Ethernet transceiver` drives and receives the analogue
   signals on the cable. It recovers the clock of the incoming signal and
   agrees the link speed with the device at the other end of the cable
   (see :doc:`../phy-electrical/index`). It connects to the cable through
   :doc:`coupling transformers <../magnetics/index>`.
Media access controller
   The :term:`media access controller (MAC) <Media access controller>` deals
   only in bytes. It sends and receives whole :term:`frames <frame>`, adds
   and checks the start of each frame and its checksum (:clause:`3`), and
   decides when a frame may be sent (:clause:`4`). In evampire this job is
   done by the :term:`forwarding logic`.

:term:`RGMII` (reduced gigabit media independent interface) is the set of
digital signals between these two chips. "Media independent" means that the
media access controller does not need to know what kind of cable the
transceiver drives. RGMII is an industry specification, not an IEEE
standard (:std:`RGMII 1.3 <rgmii-1-3>`, :std:`RGMII 2.0 <rgmii-2-0>`).
Gigabit Ethernet transceivers that support it include the Texas
Instruments DP83867 [RGMII-DP83867]_ and the Microchip KSZ9031RNX
[RGMII-KSZ9031]_, which these pages use as examples.

evampire uses RGMII in the board configuration with external transceivers
(see :numref:`tab-power-board-configs`). :numref:`fig-rgmii-connection` shows
one port; evampire has one such interface for port A and one for port B
(see :doc:`../../architecture/index`).

.. _rgmii-six-signals:

Signals in each direction
-------------------------

Each direction has a clock, a control signal and four data bits
(:std:`RGMII 2.0 <rgmii-2-0>` Table 1). The transmitting chip sends its
clock together with its data, and the receiving chip samples the data with
that clock. This is called
:wikipedia:`source-synchronous <Source-synchronous>` timing.

.. list-table:: RGMII signals, with the direction seen from evampire
   :name: tab-rgmii-signals
   :header-rows: 1
   :widths: 20 15 65

   * - Signal
     - Direction
     - Meaning
   * - TXC
     - Out
     - Transmit clock, generated by evampire
   * - TX_CTL
     - Out
     - Transmit control: "transmit enable" and "transmit error"
   * - TXD[3:0]
     - Out
     - Transmit data, four bits on each clock edge
   * - RXC
     - In
     - Receive clock, recovered by the transceiver from the cable and
       running also between frames
   * - RX_CTL
     - In
     - Receive control: "data valid" and "receive error"
   * - RXD[3:0]
     - In
     - Receive data, four bits on each clock edge

:numref:`tab-rgmii-signals` uses the names in the RGMII specification.
Transceiver datasheets use other names for the same pins, listed in
:numref:`tab-rgmii-other-names`.

   :name: tab-rgmii-other-names
   :header-rows: 1
   :widths: 30 70

   * - RGMII name
     - Names in datasheets
   * - TXC
     - GTX_CLK, TX_CLK
   * - TX_CTL
     - TX_EN, TX_CTRL
   * - TXD[3:0]
     - TD[3:0]
   * - RXC

   * - RX_CTL
     - RX_DV, RX_CTRL

How the clock, control and data signals carry bytes at each speed is
described on :doc:`data`. Each transceiver also has a slower management
interface, MDC and MDIO, for reading its status and changing its settings
(see :doc:`mdio`).

.. _rgmii-full-duplex:

Full and half duplex
--------------------

A link runs in
:wikipedia:`full duplex <Duplex_(telecommunications)>`, where both ends may
send at the same time, or in half duplex, where only one end sends at a
time. Half duplex also needs "carrier sense" (the other end is sending) and
"collision" (both ends sent at once), the signals CRS and COL of the MII
(:clause:`22.2.2.11`, :clause:`22.2.2.12`). RGMII has no wires for them and
recovers them from RX_CTL and RXD (:std:`RGMII 2.0 <rgmii-2-0>`
section 3.4.2). evampire runs its links in full duplex only (see
:doc:`speed-policy`), so it does not use them.

.. _rgmii-mii-gmii:

MII, GMII and RGMII
-------------------

RGMII is a reduced form of two interfaces defined in IEEE 802.3
(:wikipedia:`media-independent interface <Media-independent_interface>`):

:term:`MII`
   For 10 and 100 Mbit/s (:clause:`22`). Four data bits in each direction
   are sampled on the rising edge of a clock of 25 % of the data rate,
   2.5 MHz or 25 MHz (:clause:`22.2.2.1`). The LAN91C111 datasheet describes
   the same interface [RGMII-LAN91C111]_ section 7.5.4.
:term:`GMII`
   For 1000 Mbit/s (:clause:`35`). Eight data bits in each direction are
   sampled on the rising edge of a 125 MHz clock (:clause:`35.2.2.1`),
   together with a "data valid" and an "error" signal.

.. list-table:: Data signals of MII, GMII and RGMII in each direction
   :name: tab-rgmii-mii-gmii
   :header-rows: 1
   :widths: 25 25 25 25

   * - Interface
     - Data bits
     - Clock (MHz)
     - Clock edges used
   * - MII
     - 4
     - 2.5 or 25
     - 1
   * - GMII
     - 8
     - 125
     - 1
   * - RGMII
     - 4
     - 2.5, 25 or 125
     - 2

:numref:`tab-rgmii-mii-gmii` compares the three. RGMII uses both clock
edges, so four data wires carry the eight bits of a GMII byte. It also folds "valid" and "error" into one control wire. The
names of the GMII signals, such as "receive data valid" (RX_DV) and
"receive error" (RX_ER), are still used to describe what the RGMII control
wire carries (:clause:`35.2.2.7`, :clause:`35.2.2.9`).

GMII uses 24 signals for one port. Each direction has 8 data bits, a clock,
a "valid" or "enable" signal and an error signal, and the port has CRS and
COL ([RGMII-DP83867]_ section 5 lists them). RGMII uses 12: 4 data bits, a
clock and a control signal in each direction. The DP83867 datasheet gives
the same counts ([RGMII-DP83867]_ section 7.4.1.1).
